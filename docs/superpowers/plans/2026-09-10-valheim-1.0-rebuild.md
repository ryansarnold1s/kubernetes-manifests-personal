# Valheim 1.0 Rebuild Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stuck pre-1.0 Valheim server with a fresh 1.0 server on the `indifferentbroccoli/valheim-server-docker` image, a fresh world, and a three-artifact mod layer (BepInExPack, Jotunn, ValheimPlus), all pinned and checksummed in git.

**Architecture:** Same eight files in `valheim/`, edited in place. A slimmed `install-mods.sh` runs as an initContainer and owns the whole BepInEx layer on the game PVC (`/valheim`), writes the image's `.bepinex_version` marker, applies config pins, prunes unlisted plugins, and writes `adminlist.txt` to the world PVC (`/valheim-saves`). The game container runs the image with `BEPINEX_ENABLED=true` and no `MODS`. Both PVCs are deleted and recreated empty. The installer gets a local bash test harness so its install, prune, checksum and config-applier paths are exercised before anything touches the cluster.

**Tech Stack:** Kubernetes on Talos, Longhorn, MetalLB, `kubectl` from Git Bash or PowerShell with `KUBECONFIG` set in `.claude/settings.local.json`, bash 5 + unzip + sha256sum + awk + Python 3 locally for the test harness.

**Spec:** `docs/superpowers/specs/2026-09-10-valheim-1.0-rebuild-design.md`

```yaml
# BepInEx framework, server-side mods, and per-mod config, applied by the `fetch-mods`
# initContainer in deployment.yaml straight into the live install on the valheim-server PVC.
#
# WHY AN INIT CONTAINER: Kubernetes has no bind-mount for a workstation file, so a DLL has to
# reach the PVC somehow. The pod has outbound internet, so fetching pinned, checksummed
# releases at pod start is declarative and reproducible from an empty PVC.
#
# WHY THE INIT CONTAINER INSTALLS BEPINEXPACK TOO (and not the image): the image downloads
# BepInExPack only when /valheim/BepInEx is ABSENT. This container has to create
# BepInEx/plugins/<mod>/ before the game container's first boot, so the image would see the
# directory, skip its own install, and the game would boot vanilla with no error. Owning the
# pack also owns /valheim/.bepinex_version, which the image's start.sh reads to choose the
# doorstop env var names -- no marker means "legacy 5.4.22", the old names, and BepInEx never
# loads. So: BEPINEX_ENABLED=true in configmap.yaml (for the LD_PRELOAD/doorstop env), the
# pack from here, and the image's own MODS variable left unset so its downloader never runs.
#
# ADDING/UPGRADING: add or edit a line in MODS, then apply + rollout restart. The installer
# keys off "<version> <sha256>", so changing either reinstalls just that entry. Checksum:
#   kubectl exec -n valheim deploy/valheim -c valheim -- sh -c 'curl -fsSL -o /tmp/m.zip "<url>" && sha256sum /tmp/m.zip'
#
# REMOVING: delete the line, apply, restart. Any plugins/<dir> not named in MODS is pruned,
# with a breaker that refuses more than 2 removals in one boot (a truncated MODS block looks
# exactly like a mass removal). Only mods that register no prefabs are free to remove --
# a mod that added items or creatures leaves orphaned ZDOs in the world save.
#
# The first install of any NEW mod costs two applies: a mod does not write its .cfg until
# it has booted once, and MOD_CONFIG cannot name a section that does not exist yet.
apiVersion: v1
kind: ConfigMap
metadata:
  name: valheim-mods
  namespace: valheim
  labels:
    app: valheim
data:
  # name  version  url  sha256  layout
  #
  # layout=pack    -> BepInExPack_Valheim/* is copied over /valheim (the framework itself)
  # layout=plugins -> the zip has a plugins/ dir; its contents go to BepInEx/plugins/<name>/
  # layout=bepinex -> the zip nests under BepInEx/plugins/ (ValheimPlus does this)
  # layout=root    -> the .dll sits at the zip root; it goes to BepInEx/plugins/<name>/
  #
  # Checksums captured from the real downloads on 2026-09-10. Layouts verified with unzip -l,
  # not assumed from the store page.
  #
  # ValheimPlus 10.0.2 declares BepInExPack 5.4.2350; Jotunn 2.30.0 declares 5.4.2333, which
  # 5.4.2350 satisfies. All three shipped Valheim 1.0 releases on 2026-09-09/10.
  #
  # CLIENT INSTALL: ValheimPlus is pinned at its defaults with enforceMod off, so a client
  # without it can still join. Players who want V+ features install the same version.
  MODS: |
    BepInExPack_Valheim  5.4.2350  https://thunderstore.io/package/download/denikson/BepInExPack_Valheim/5.4.2350/               37a91c000b4e88f2ed7a4bd7d812239852d2e36cbf0ff0a9f5faacfba46b105f  pack
    Jotunn               2.30.0    https://thunderstore.io/package/download/ValheimModding/Jotunn/2.30.0/                        f7f218ac3f97b27a7e65d62b5ebe7c29b93129bf3e56cf41b6870bef1ef161fd  plugins
    ValheimPlus          10.0.2    https://thunderstore.io/package/download/Grantapher/ValheimPlus_Grantapher_Temporary/10.0.2/  6fece0e93ffe3604210fa04dd58a2773d22c4334ee1f0069ac6a6977d89acb1c  bepinex
  # Per-mod config, declared here instead of hand-edited on the PVC. One line per key:
  #   <file under BepInEx/config>|<section>|<key>|<value>
  #
  # Two parsers, two failure modes. valheim_plus.cfg is parsed by V+'s own INI reader
  # (true/false, "key=value" with no spaces, CRLF line endings). BepInEx-bound mods use
  # "Key = Value" and Toggle enums (On/Off). The applier preserves whichever separator style
  # the file already uses. A rejected BepInEx value logs "could not be parsed" in the game
  # container; a rejected V+ value logs NOTHING -- verify V+ by reading the file back.
  #
  # ⚠️ Enabling a V+ section makes EVERY key in it live. Pin them all, including the ones
  # staying at default, or a future V+ default change takes effect silently.
  #
  # ⚠️ A pin whose value equals the mod's default is inert and unverifiable -- it reads back
  # correct even if the section name is wrong. The [Fermenter] enabled=true line below is the
  # sentinel that proves the applier reached this file; every other key in that section is
  # pinned at its generated default so enabling it changes no behaviour.
  #
  # Populated after the first boot, from the file V+ actually generated -- see README.md.
  MOD_CONFIG: |
  install-mods.sh: |
    #!/bin/bash
    # Idempotent, checksum-verified installer for BepInExPack + server-side mods, plus
    # declarative per-mod config and the admin list. Runs as an initContainer and writes
    # straight into the live install -- this image has no staged copy and no bootstrap rsync.
    set -euo pipefail

    # SERVER/SAVES/TMP are overridable ONLY so valheim/tests/test-install-mods.sh can run this
    # against a temp directory. deployment.yaml sets none of them.
    SERVER=${SERVER:-/valheim}                  # the image's force_install_dir
    SAVES=${SAVES:-/valheim-saves}              # the image's SAVE_DIR; adminlist.txt lives here
    TMP=${TMP:-/tmp/mods}                       # emptyDir, so a failed download never litters a PVC
    PLUGINS="$SERVER/BepInEx/plugins"           # live plugin dir
    BEPINEX_CONFIG="$SERVER/BepInEx/config"     # a real directory here, not a symlink
    STATE="$SERVER/.mod-state"                  # install markers; deliberately NOT under plugins/

    mkdir -p "$PLUGINS" "$BEPINEX_CONFIG" "$STATE" "$TMP"

    installed=0; skipped=0

    # Is this entry already present at the pinned version+sha? The pack has no plugins/<name>
    # directory, so it is tested by its two signature files instead.
    is_installed() {
      local name=$1 layout=$2 marker="$STATE/$name" want=$3
      [ -f "$marker" ] && [ "$(cat "$marker")" = "$want" ] || return 1
      case "$layout" in
        pack) [ -f "$SERVER/.bepinex_version" ] && [ -f "$SERVER/BepInEx/core/BepInEx.dll" ] ;;
        *)    [ -d "$PLUGINS/$name" ] ;;
      esac
    }

    install_one() {
      local name=$1 ver=$2 url=$3 sha=$4 layout=$5
      local marker="$STATE/$name" want="$ver $sha"

      case "$layout" in pack|plugins|bepinex|root) ;;
        *) echo "[FAIL ] $name: unknown layout '$layout'" >&2; exit 1 ;;
      esac

      if is_installed "$name" "$layout" "$want"; then
        echo "[skip ] $name $ver (already installed)"
        skipped=$((skipped + 1))
        return 0
      fi

      echo "[fetch] $name $ver"
      local zip="$TMP/$name.zip"
      curl -fsSL --retry 3 --retry-delay 5 --max-time 900 -o "$zip" "$url"

      local got
      got=$(sha256sum "$zip" | cut -d' ' -f1)
      if [ "$got" != "$sha" ]; then
        echo "[FAIL ] $name checksum mismatch" >&2
        echo "         want $sha" >&2
        echo "         got  $got" >&2
        echo "         Refusing to install. This is executable code that runs inside the" >&2
        echo "         server -- a mismatch means the artifact changed or was tampered with." >&2
        exit 1
      fi

      local ex="$TMP/x-$name"
      rm -rf "$ex"; mkdir -p "$ex"
      unzip -q -o "$zip" -d "$ex"

      case "$layout" in
        pack)
          # Replace the framework's own directories so an upgrade cannot leave stale core
          # files behind. plugins/ and config/ are NOT touched: plugins are managed per entry
          # below, and config/ holds the per-mod .cfg files the applier maintains. The pack's
          # own BepInEx.cfg is copied over the existing one; nothing here pins BepInEx.cfg.
          rm -rf "${SERVER:?}/BepInEx/core" "${SERVER:?}/doorstop_libs"
          cp -a "$ex/BepInExPack_Valheim/." "$SERVER/"
          # The image's start.sh reads this to choose doorstop env var names. Absent => it
          # assumes 5.4.22 and exports the OLD names, and BepInEx never loads. See README.
          echo "$ver" > "$SERVER/.bepinex_version"
          ;;
        *)
          # Replace rather than merge, so an upgrade cannot leave stale files from the old version.
          rm -rf "${PLUGINS:?}/${name:?}"
          mkdir -p "$PLUGINS/$name"
          case "$layout" in
            plugins) cp -a "$ex/plugins/." "$PLUGINS/$name/" ;;
            bepinex) cp -a "$ex/BepInEx/plugins/." "$PLUGINS/$name/" ;;
            root)    find "$ex" -maxdepth 1 -type f -name '*.dll' -exec cp -a {} "$PLUGINS/$name/" \; ;;
          esac
          # Thunderstore's optional config/ maps to BepInEx/config/.
          if [ -d "$ex/config" ]; then
            echo "[     ] $name: installing bundled config/ -> $BEPINEX_CONFIG/"
            cp -a "$ex/config/." "$BEPINEX_CONFIG/"
          fi
          ;;
      esac

      rm -rf "$ex" "$zip"
      echo "$want" > "$marker"
      echo "[ok   ] $name $ver"
      installed=$((installed + 1))
    }

    # Sets one key in a .cfg, touching nothing else. Handles: key present in section (replace
    # in place), key absent but section present (append to that section), section absent
    # (create at end), file absent (create it -- BepInEx honours a partial config and fills in
    # the rest on first load).
    # ⚠️ DO NOT "clean up" the norm() calls. CRLF handling is load-bearing: ValheimPlus writes
    # valheim_plus.cfg with \r\n, so "[Fermenter]\r" never equals "[Fermenter]" without it, and
    # every V+ pin would miss its section and append a duplicate at the end -- silently, while
    # logging success. Zero-width/BOM stripping is defensive: some Thunderstore mods prefix
    # keys with U+200B to force sort order, and a literal compare then appends a second, plain
    # key the mod ignores.
    # Separator style is preserved per line: BepInEx writes "Key = Value", V+ writes "key=value"
    # and parses its own INI, so forcing spaces into valheim_plus.cfg risks a missed key.
    CFG_AWK='
    function norm(s,   t) { t=s; gsub(zw,"",t); gsub(bom,"",t); gsub(/\r/,"",t); gsub(/^[ \t]+|[ \t]+$/,"",t); return t }
    BEGIN { insec=0; done=0; sawsec=0 }
    {
      line=$0
      if (line ~ /^[ \t]*\[/) {
        if (insec && !done) { print k sep v; done=1 }
        insec = (norm(line) == "[" norm(sec) "]"); if (insec) sawsec=1
        print line; next
      }
      if (insec && !done && line !~ /^[ \t]*[#;]/) {
        eq = index(line, "=")
        if (eq > 0) { lhs = substr(line,1,eq-1)
          if (norm(lhs) == norm(k)) { okey=lhs; gsub(/[ \t]+$/,"",okey)
            s = (lhs ~ /[ \t]$/) ? " = " : "="
            cr = (line ~ /\r$/) ? "\r" : ""
            print okey s v cr; done=1; next } }
      }
      print line
    }
    END { if (!done) { if (insec) print k sep v
           else if (!sawsec) { print ""; print "[" sec "]"; print k sep v } } }'

    ZW=$(printf '\342\200\213')    # U+200B zero width space
    BOM=$(printf '\357\273\277')   # U+FEFF byte order mark

    set_cfg() {
      local file=$1 section=$2 key=$3 value=$4
      local path="$BEPINEX_CONFIG/$file"
      if [ ! -f "$path" ]; then
        printf '[%s]\n\n%s = %s\n' "$section" "$key" "$value" > "$path"
        echo "[cfg  ] $file [$section] $key = $value (created)"
        return 0
      fi
      awk -v zw="$ZW" -v bom="$BOM" -v sep="=" -v sec="$section" -v k="$key" -v v="$value" \
        "$CFG_AWK" "$path" > "$path.new"
      mv "$path.new" "$path"
      echo "[cfg  ] $file [$section] $key = $value"
    }

    echo "=== valheim mod installer ==="

    # Names MODS still lists. Computed FIRST so an empty or unparseable MODS aborts before any
    # download, and so the prune below cannot disagree with the install loop about the set.
    keep=$(while read -r name _rest; do
             [ -z "${name:-}" ] && continue
             case "$name" in \#*) continue ;; esac
             printf '%s\n' "$name"
           done <<< "${MODS:-}")

    # An EMPTY MODS -- the ConfigMap key missing, or its block scalar emptied -- must never be
    # read as "delete everything". This guards that one shape of bad input. A TRUNCATED MODS
    # still parses to a valid non-empty set and walks past here; the bulk-prune breaker below
    # is what catches that.
    if [ -z "$keep" ]; then
      echo "[FAIL ] MODS parsed to an empty set -- refusing to run" >&2
      exit 1
    fi

    while read -r name ver url sha layout; do
      [ -z "${name:-}" ] && continue
      case "$name" in \#*) continue ;; esac
      install_one "$name" "$ver" "$url" "$sha" "$layout"
    done <<< "$MODS"

    # --- prune: plugin directories no longer listed in MODS ----------------------------
    # ⚠️ Every rm below uses ${VAR:?}, so an unset or empty path aborts instead of expanding
    # to a bare root. Do NOT rewrite these as plain "$VAR".
    #
    # ⚠️ The herestring in is_kept is deliberate -- do NOT "simplify" it to `printf | grep -q`.
    # Under pipefail, grep -q exiting on a match before printf finishes can SIGPIPE printf and
    # invert the test, deleting a mod MODS still lists. A herestring has no pipeline.
    is_kept() { grep -qxF "$1" <<< "$keep"; }

    # Only DIRECTORIES under plugins/ are candidates. The pack's core/, config/ and doorstop
    # files live outside plugins/, and a loose file dropped in by the image (MaxPlayerCount.dll,
    # only ever present if MAX_PLAYERS is changed from 10) is a file, not a directory.
    doomed=$( [ -d "$PLUGINS" ] && for d in "$PLUGINS"/*/; do
                [ -d "$d" ] || continue
                n=$(basename "$d"); is_kept "$n" || printf '%s\n' "$n"
              done || true )
    if [ -z "$doomed" ]; then doomed_n=0
    else doomed_n=$(printf '%s\n' "$doomed" | wc -l | tr -d '[:space:]'); fi

    # --- bulk-prune circuit breaker -----------------------------------------------------
    # ⚠️ DO NOT raise this threshold to push a large cleanup through, and do NOT delete it on the
    # grounds that the empty-set guard covers bad input. It does not: a MODS block clipped
    # mid-list still parses to a valid non-empty set, and the prune would read every mod below
    # the cut as deliberately removed. A deliberate removal in this repo is one mod at a time;
    # more than two in one boot is the signature of a clipped block. Failing the initContainer
    # keeps the pod down until a human looks -- recoverable. A wrongly pruned mod that had
    # registered prefabs is not: its placed objects are orphaned ZDOs in the world save.
    if [ "$doomed_n" -gt 2 ] && [ "${PRUNE_ALLOW_BULK:-}" != "yes" ]; then
      echo "[FAIL ] prune would remove $doomed_n mods in a single boot: $(printf '%s ' $doomed)" >&2
      echo "         Refusing. More than 2 at once usually means the MODS block in" >&2
      echo "         mods-configmap.yaml was truncated, not that this many mods were dropped." >&2
      echo "         If this removal really is intended, add env PRUNE_ALLOW_BULK=\"yes\" to the" >&2
      echo "         fetch-mods container in deployment.yaml, apply, let it boot once, remove it." >&2
      exit 1
    fi

    echo "=== pruning plugins no longer in MODS ($doomed_n to remove) ==="
    for n in $doomed; do
      echo "[prune] removing $n (not in MODS)"
      rm -rf "${PLUGINS:?}/${n:?}"
    done
    # Orphaned markers go too, so re-adding a mod later reinstalls it instead of being skipped
    # by a stale marker. Markers are regenerable metadata, so they are not counted by the breaker.
    for m in "$STATE"/*; do
      [ -f "$m" ] || continue
      n=$(basename "$m")
      is_kept "$n" || { echo "[prune] marker: removing $n"; rm -f "${STATE:?}/${n:?}"; }
    done

    echo "=== applying per-mod config ==="
    while IFS='|' read -r file section key value; do
      [ -z "${file:-}" ] && continue
      case "$file" in \#*) continue ;; esac
      set_cfg "$file" "$section" "$key" "$value"
    done <<< "${MOD_CONFIG:-}"

    # --- adminlist -----------------------------------------------------------------------
    # The image does nothing with admins. Valheim reads <savedir>/adminlist.txt at start and
    # re-reads it periodically; the header line is the one the game itself writes. Rewritten
    # every boot from ADMINLIST_IDS, so a ConfigMap edit + restart is the whole procedure.
    mkdir -p "$SAVES"
    {
      echo "// List admin players ID  ONE per line"
      for id in ${ADMINLIST_IDS:-}; do echo "$id"; done
    } > "$SAVES/adminlist.txt"
    echo "[admin] wrote $SAVES/adminlist.txt ($(( $(wc -l < "$SAVES/adminlist.txt") - 1 )) ids)"

    # No chown here: the image's init.sh chown -Rs both volumes on every start and then runs
    # the game as root anyway.

    echo "=== done: $installed installed, $skipped already present ==="
    echo "--- BepInEx/plugins ---"
    ls -1 "$PLUGINS"
```

apiVersion: apps/v1
kind: Deployment
metadata:
  name: valheim
  namespace: valheim
  labels:
    app: valheim
spec:
  replicas: 1
  strategy:
    # Recreate: RollingUpdate deadlocks on the ReadWriteOnce Longhorn volumes (the new pod
    # cannot mount while the old pod holds them).
    type: Recreate
  selector:
    matchLabels:
      app: valheim
  template:
    metadata:
      labels:
        app: valheim
    spec:
      # The image traps SIGTERM, sends SIGINT to the game and waits for it to finish saving.
      # Valheim needs up to ~2 minutes for that on a large world. The image's own compose
      # example says 30s; that is not enough and was deliberately not copied.
      terminationGracePeriodSeconds: 120
      # No fsGroup: init.sh chown -Rs both volumes itself on every start, and kubelet doing a
      # second recursive pass over a multi-GB game install on every mount buys nothing.
      initContainers:
      # Installs BepInExPack + the pinned mod set + per-mod config + adminlist.txt BEFORE the
      # game container starts. Writes straight into the live install on /valheim: this image
      # has no staged copy and no bootstrap rsync. See mods-configmap.yaml for why this
      # container, and not the image, installs BepInExPack.
      #
      # Idempotent: markers in /valheim/.mod-state are keyed on version+sha256, so a normal
      # restart re-downloads nothing. A checksum mismatch fails this container and the pod
      # will not start -- intentional for executable code, and it only gates a first install
      # or a version change, so a Thunderstore outage cannot take down a provisioned server.
      #
      # Reuses the game image deliberately: already pulled on the node, ships bash, curl,
      # unzip and sha256sum, adds no new supply-chain surface.
      - name: fetch-mods
        image: indifferentbroccoli/valheim-server-docker:v1.0.11@sha256:3702926c5e174e4e28189136b512a034cacb9b57636c5d29d978e9a97c6e2f98
        imagePullPolicy: IfNotPresent
        # Bypasses the image's ENTRYPOINT (init.sh), which would try to install the game.
        command: ["/bin/bash", "/scripts/install-mods.sh"]
        env:
        # Explicit keys, not envFrom: valheim-mods also holds install-mods.sh, which is not a
        # valid env var name -- envFrom would skip it and emit an InvalidEnvironmentVariableNames
        # event on every pod start.
        - name: MODS
          valueFrom:
            configMapKeyRef:
              name: valheim-mods
              key: MODS
        - name: MOD_CONFIG
          valueFrom:
            configMapKeyRef:
              name: valheim-mods
              key: MOD_CONFIG
        - name: ADMINLIST_IDS
          valueFrom:
            configMapKeyRef:
              name: valheim-config
              key: ADMINLIST_IDS
        volumeMounts:
        - name: server
          mountPath: /valheim
        - name: saves
          mountPath: /valheim-saves
        - name: mod-scripts
          mountPath: /scripts
          readOnly: true
        - name: mod-tmp
          mountPath: /tmp/mods
        resources:
          requests:
            cpu: "200m"
            memory: "128Mi"
          limits:
            memory: "512Mi"
      containers:
      - name: valheim
        image: indifferentbroccoli/valheim-server-docker:v1.0.11@sha256:3702926c5e174e4e28189136b512a034cacb9b57636c5d29d978e9a97c6e2f98
        imagePullPolicy: IfNotPresent
        ports:
        - name: game
          containerPort: 2456
          protocol: UDP
        - name: query
          containerPort: 2457
          protocol: UDP
        envFrom:
        - configMapRef:
            name: valheim-config
        env:
        - name: SERVER_PASSWORD
          valueFrom:
            secretKeyRef:
              name: valheim-secrets
              key: server-password
        volumeMounts:
        # /valheim is the image's force_install_dir; /valheim-saves is its SAVE_DIR (-savedir).
        - name: server
          mountPath: /valheim
        - name: saves
          mountPath: /valheim-saves
        # Deliberately no livenessProbe: it would SIGKILL the server mid-world-save. The
        # Deployment restarts the container if it exits.
        #
        # The pattern MUST stay bracketed as '[v]alheim_server'. `pgrep -f` matches full command
        # lines, so a bare `pgrep -f valheim_server` matches the probe's own `sh -c` process and
        # returns 0 unconditionally -- a probe that can never fail. (The `> /dev/null` keeps that
        # shell alive: without a redirect bash exec-replaces itself.) '[v]alheim_server' matches
        # the real process but not the literal shell argv. Verified against a name that does not
        # exist: bare form -> 0, bracketed -> 1. Do not "simplify" the brackets away.
        startupProbe:
          exec:

## How the image behaves

Read from its scripts, not its README. Each of these shaped a manifest comment.

- **Two volumes.** `/valheim` is the SteamCMD install dir and holds BepInEx too;
  `/valheim-saves` is `-savedir`, so the world is `/valheim-saves/worlds_local/`.
- **`PUBLIC` is dead code.** `start.sh` tests `PUBLIC_ENABLED`, which nothing sets. The
  server is always private.
- **BepInExPack is installed by *our* initContainer, not the image.** The image only installs
  it when `/valheim/BepInEx` is absent, and our plugins directory defeats that check on the
  first boot. The initContainer also writes `/valheim/.bepinex_version`; without that marker
  `start.sh` exports the legacy doorstop variable names and BepInEx silently never loads.
  `BEPINEX_ENABLED=true` is still required: it is what makes `start.sh` export the
  `LD_PRELOAD`/doorstop env at all.
- **The image's `MODS` variable stays unset.** Its downloader wipes and re-fetches every mod
  unverified on every boot and flattens each zip into one directory.
- **`MAX_PLAYERS` stays unset.** Any value other than 10 silently installs the image's
  bundled MaxPlayerCount mod.
- **The game runs as root.** `init.sh` requires `PUID`/`PGID`, usermods the steam user,
  `chown -R`s both volumes, then starts the game without dropping privileges. Accepted for a
  single-operator LAN server in a `baseline` namespace. Do not add `runAsUser`; it breaks
  the entrypoint.
- **No cron, no zips, no adminlist handling.** Backups are Valheim's native rolling set
  (`KEEP_BACKUPS` and friends), Longhorn, and CloudCasa. `adminlist.txt` is written by the
  initContainer from `ADMINLIST_IDS`.
- **Game updates are deliberate.** `UPDATE_ON_START=false`; SteamCMD only runs when the
  binary is absent. See Common tasks for the update procedure.
- **`NO_BUILD_COST=true` is `-setkey nobuildcost`**, a global key persisted into the world
  save. Removing the env does not remove the key; reversal is `removekey nobuildcost` in the
  admin F5 console, then a restart.

## Operating notes

- **Never lower `terminationGracePeriodSeconds` below 120.** The image sends SIGINT and
  waits; Valheim needs time to flush the world. The image's compose example says 30s and is
  wrong for anything but an empty world.
- **`strategy: Recreate` is required.** RollingUpdate deadlocks on the ReadWriteOnce volumes.
- **Startup and readiness probes only, deliberately no liveness probe.** A liveness probe
  would SIGKILL the server mid-save.
- **Never unbracket the probe pattern.** `pgrep -f` matches full command lines, so an
  unbracketed `pgrep -f valheim_server` matches the probe's own `sh -c` process and returns
  0 no matter what. `[v]alheim_server` matches the real process but not the literal shell
  argv. Verify any change against a name that does not exist, not just a healthy server:

  ```powershell
  # want: exit=1
  kubectl exec -n valheim deploy/valheim -- sh -c 'pgrep -f "[Z]ZZNOSUCH" > /dev/null; echo exit=$?'
  ```

  Single-quoted outer string: PowerShell would eat `$?` inside double quotes. Testing an
  *unbracketed* candidate inline is not valid either: your own test command's argv contains
  the pattern, so it self-matches exactly the way the probe does. Write it to a script file
  in the container and run that instead.
- **No CPU limit, deliberately.** CFS throttling shows up in-game as rubber-banding.
- **No `nodeSelector`/`affinity`.** The three small nodes are control-plane and tainted, so
  the four identical workers are already the only candidates.
- **Requests are headroom, not usage.** 2 CPU / 5Gi requested. Measure under player load
  before tuning; an empty world idles far below this.
- **`externalTrafficPolicy: Local` + pod reschedule = brief outage** while MetalLB
  re-announces from the new node. Expected.
- **Never write the live server password into a tracked file**, not even as a grep pattern.
  Derive it from the Secret at runtime if needed.

### Memory and world growth

An OOMKill is SIGKILL and bypasses the grace period, so the 8Gi memory limit is a
world-corruption risk, not just an availability one. No monitoring stack exists; check by
hand, and under player load, not idle:

```powershell
$p = kubectl get pod -n valheim -l app=valheim -o jsonpath='{.items[0].metadata.name}'
$top = (kubectl top pod -n valheim --no-headers | Where-Object { $_ -match '\S' }) -join "`n"
if ($top -match '(\d+)m\s+(\d+)Mi') {
  $cpu = $matches[1]; $memMi = [int]$matches[2]
  Write-Output "memory : ${memMi}Mi of 8192Mi limit  ($([math]::Round($memMi/8192*100,1))%)"
  Write-Output "cpu    : ${cpu}m"
}
$zdo = ((kubectl logs -n valheim $p -c valheim --tail=600 | Select-String "ZDOS:") | Select-Object -Last 1) -replace '.*ZDOS:(\d+).*','$1'
$db  = kubectl exec -n valheim $p -c valheim -- stat -c %s /valheim-saves/worlds_local/TreeFellMeAgain.db
Write-Output "ZDOs   : $zdo"
Write-Output "world  : $([math]::Round($db/1MB,1)) MiB"
```

The `-join` and blank-line filter are load-bearing: kubectl returns a string array.

| Reading | Meaning |
|---|---|
| under ~5500Mi | fine |
| ~5500–6500Mi sustained | raise the limit; it is not a reservation |
| over ~6500Mi | raise it now, before a save lands on the ceiling |

The previous world reached 1.5M ZDOs / 72 MiB and a 3–4s save freeze in six weeks. The
freeze is `PrepareSave` cloning world state in memory on the main thread; faster storage
does not help, and raising `SAVE_INTERVAL` only trades crash-loss for comfort.

## Modding (BepInEx)

`mods-configmap.yaml` is the whole story: `MODS` is the pinned table (BepInExPack itself is
the first row), `MOD_CONFIG` is the per-mod config, and `install-mods.sh` applies both from
the `fetch-mods` initContainer on every boot.

- **Add or upgrade:** edit the row, apply, `rollout restart`. Get the checksum from the real
  download (command in the file's header comment). A **new** mod costs two applies: it
  writes its `.cfg` on first boot, and `MOD_CONFIG` cannot name a section that does not
  exist yet. Enumerate the generated file before pinning anything; upstream docs
  understate the key set and get types wrong.
- **Remove:** delete the row, apply, restart. The prune refuses more than 2 removals in one
  boot; a truncated `MODS` block looks exactly like a mass removal. Only mods that register
  no prefabs are free to remove.
- **Test the installer before changing it:** `bash valheim/tests/test-install-mods.sh` from
  the repo root. It runs the script from the ConfigMap against a temp directory with fake
  zips and exercises install, skip, checksum refusal, prune, the breaker, the config applier
  on a CRLF file, and the adminlist. `install-mods.sh` must stay the **last** key in the
  ConfigMap; the harness extracts it by "everything after the key line".
- **Recon a candidate mod inside the running container first**, per the repo `CLAUDE.md`:
  sha256, zip layout, config section names, kick behaviour
  (`RemoveDisconnectedPeerFromVerified`), prefab registration, Thunderstore `date_updated`.
